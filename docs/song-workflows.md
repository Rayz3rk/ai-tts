# 三种歌声工作方式

## 已有演唱，换成目标音色

打开 **06 目标音色翻唱**：

1. 选择充分训练或导入的 RVC v2 目标音色模型（`.pth`，可带 `.index`）。
2. 上传演唱干声，或点击“载入测试干声”。干声提供歌词、旋律和节奏；模型决定转换后的音色。
3. 通常先用升降调 0，试听后再按音域调整。需要伴奏时，展开高级设置上传独立伴奏。
4. 点击生成，结果可播放、下载并自动登记到素材库。

含伴奏的整首歌曲应先分离人声；此入口不自动做人声分离。

随项目提供的 `outputs/samples/singing-dry-demo.wav` 是绮萱原音色的无伴奏歌声，歌词“让音乐带来好心情”，旋律 120 BPM、约 4.5 秒，另保留约 0.15 秒起音和收尾。它用于转换测试，不能用作音色训练数据。

当前名为“RVC 合成样本验收音色”的模型只用合成样本完成了 **1 次参数更新**，仅证明训练、导出、注册、转换流程运行正常。它不代表正式翻唱质量。训练个人音色需要本人干净录音，或导入已训练好的适用模型。

## 新歌词，套入明确的旋律

打开 **07 歌词与旋律演唱**，优先使用两种批量方式：

- **整首 MIDI**：先输入歌词，导入单声部旋律 MIDI；多轨文件需要选择旋律轨道。保留文件原有速度变化。每个音符对应一个字/拼音；一字多音的后续位置用 `-` 占位。
- **整段简谱或音名**：歌词整段粘贴；旋律用空格分开，填 BPM 后自动计算秒数。默认 120 BPM，每拍 0.5 秒。

例如：

```text
歌词：让音乐带来好心情
旋律：1 2 3 5 | 4 3 2 1:2
BPM：120
```

共 8 个字、9 拍，旋律约 4.5 秒。`:2` 为两拍，`:0.5` 为半拍；`0` / `rest` 休止，`-` 延长前一音，`D4~` 将前一个字延续到新音高。数字 1–7 采用 C 大调，`1+` / `1-` 升降八度，也可写 `C4`、`F#4` 等音名。

修改批量歌词、旋律或 BPM 后，点击检查或生成会自动重新计算。逐音符秒数编辑位于默认收起的“逐音符高级编辑”，用于局部修正。当前支持单声部普通话/拼音、最多 2000 个音符、总长 10 分钟；长歌分乐句合成。

输出音色先使用“绮萱原音色”判断发音和旋律；选择正式 RVC 音色后可串联转换。声库输出及其转换版本不用于训练，详见声库条款。

## 只有歌词，让模型创作新歌

**08 歌词自动创作**使用 ACE-Step 1.5，由模型创作旋律、演唱和伴奏，不需要填写乐谱。歌词可用 `[Verse]`、`[Chorus]` 标记段落，输入风格和目标时长，BPM 可留空。生成的声音由歌曲模型决定，不能将含伴奏的整曲直接作为 RVC 干声输入。

本机部署：2B turbo + 0.6B 音乐语言模型，CUDA 显卡运行，单次 10–180 秒，首次建议 30 秒。歌词遵循度、曲风和人声质量需实际试听，不保证每次逐字准确或精确复现指定旋律。

### 独立环境与下载位置

- 主工作台与 TTS/RVC：根目录 `.venv`。
- 自动创作环境及固定版本源码：`studio_data/runtimes/ace-step/`，其中 `.venv` 有独立依赖。这不是先前删除的 `.venv-check` 测试环境。
- 自动创作模型：`studio_data/models/ace-step/`，约 7.2GB。下载中的文件后缀为 `.download`；`.ranges/` 保存小型续传标记，不复制一份大权重。
- 生成音频：`studio_data/audio/`。数据库记录作品名、歌词、风格、时长、种子及文件关联。
- 推理中间音频与参数：该音频目录内的 `<音频ID>-ace-step/`。
- 任务日志：`studio_data/jobs/<任务ID>/worker.log`。
- Python 安装缓存仍由 uv 的本机缓存目录管理。
- 为解决大文件流式下载断线，CUDA PyTorch 安装包在 `work/verified-wheels/` 分段续传、校验并保留；对应 `.ranges/` 仅保存续传标记。

首次安装或修复独立环境：

```powershell
.\scripts\setup-music.ps1
```

普通依赖使用清华镜像。CUDA PyTorch 的大文件优先从南京大学/上海交大的 PyTorch 专用镜像续传，并核对 PyTorch 官方 SHA256，官方源为后备；此构建不在普通 PyPI 镜像中。这里使用直接 Python 推理接口，不安装上游完整 Gradio、训练、nano-vLLM/FlashAttention 环境；音乐语言模型采用官方 PyTorch 后端。不会替换主工作台的 PyTorch/transformers。

下载记录固定的 Hugging Face revision，并验证官方 LFS SHA256；普通配置也校验 Git blob SHA1。推理设置为离线，不自动下载缺失权重。独立运行环境通过 CUDA 运算和导入检查后才写入就绪记录。

上游来源：[ACE-Step 1.5](https://github.com/ace-step/ACE-Step-1.5)，本项目固定源码 commit `ca1e85fe9430179831e6bc6be790c332190a3866`。
