# 音频模型与运行设计

## 任务范围

文本转语音支持固定音色和参考音色，用配对录音与转写对 F5 进行本地微调。歌声流程支持 RVC 目标音色训练/转换、DiffSinger 歌词与音符合成，以及两者串联。翻译、ASR、人声分离和 CosyVoice 仍保留在原 Voice-Pro 项目。

## 模型路径

- Kokoro：82M 固定音色模型，适合快速合成。预设选取已下载的本地音色向量，配置语言和语速。中文分段避免长句超过声学模型的音素长度限制。
- F5-TTS v1：CFM（条件流匹配）与 DiT；模型配置 dim=1024、depth=22、heads=16、text_dim=512、conv_layers=4。以音频提示及其转写为条件，生成目标文本的声学表示，再经 Vocos 生成波形。
- 声学配置：单声道 24000Hz，100 个 mel 频带，hop_length=256、win_length=n_fft=1024。保留官方基础模型的词表顺序；中文使用上游的拼音转换逻辑。
- 预设是模型、音色或参考音频、语速、采样步数及种子的组合。用途分类不额外训练情绪模型。

## 模块边界

歌声相关模块：`svc.py` 负责本地 ContentVec/RMVPE 与 RVC 推理，`svc_training.py` 负责无转写数据准备和完整 GAN/FM/Mel/KL 更新；`score.py` 处理 MIDI 速度映射、轨道和歌词音符对齐，`singing.py` 运行作者原始 ONNX 发音时长、音高、表现参数、声学和声码器模型。`covers.py`、`singing_api.py` 接入同一个可取消的串行任务队列与 PostgreSQL 素材/模型/训练记录。Windows 取消会终止包含虚拟环境重定向子进程在内的整个工作进程树。

| 文件 | 职责 |
| --- | --- |
| `schemas.py` | API 参数与范围校验 |
| `store.py` / `database.py` | 模型、预设、素材、数据集与训练元数据；PostgreSQL 与离线 JSON |
| `engines.py` | 官方权重显式下载、完整所需文件检查、本地推理 |
| `datasets.py` | 逐条录音检查、重采样、Arrow 准备、词表检查 |
| `training.py` | 严格载入基础权重、实际梯度更新、EMA 导出 |
| `jobs.py` / `worker.py` | 串行任务队列、工作进程、取消、持久状态和日志 |
| `api.py` / `static/index.html` | 同源工作台、API、参考音频上传和生成结果 |
| `__main__.py` | 本机服务及离线 CLI |

## 训练与导出

训练加载预训练 EMA 权重，严格匹配参数与词表；参数不匹配会停止。使用真实 mel 和配对文本计算 F5 损失，执行梯度反传、梯度裁剪、AdamW 更新及 EMA。CUDA 按能力使用 BF16 或 FP16，CPU 使用 FP32。梯度累积和激活检查点用于控制显存。

本地训练循环复用上游 CFM、DiT、Trainer、EMA 和 Accelerate，显式使用 num_workers=0，并针对短训练使用有界学习率调度，避开固定 warmup 超过训练总步数和 persistent_workers 与单进程加载的组合问题。

每次更新记录 loss。完成后导出的 `model.safetensors` 使用上游 F5 推理可读的 `ema_model.*` 权重格式，配套词表保持原索引。Web 任务自动注册产物；后续预设引用模型 ID。声码器与检查点分别存放，部署需要同时保留权重、词表和声码器。

## 任务生命周期

queued → running → succeeded / failed / cancelled。单服务进程只运行一个工作进程；多个任务排队。长任务不在 HTTP 请求线程执行。取消会终止对应工作进程，结束后释放模型与显存。服务重启将未完成任务标记为失败，保留日志；新训练从选定模型权重开始，不恢复优化器状态。

下载仅在显式操作后进行；保存官方来源和 revision。推理限制为本地资产，参考文本必须填写以避免隐式下载 ASR。预设、音频与训练数据均保存在用户的数据目录。默认只监听本机，远程监听要求令牌。

## 验收界限

单元测试覆盖业务与文件错误路径；小型真实 DiT 的训练测试检验 loss、梯度更新和 EMA 导出重载，不能证明基础模型微调质量。预训练模型实际生成的 WAV 验证推理路径。个人音色训练效果必须在用户提供真实录音后，通过独立文本试听评价。
